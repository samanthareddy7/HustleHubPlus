PART 1 Explanation:

Core functionality
 
* POST /api/auth/register — creates a user (in-memory or file-based storage is fine for now.
preferably will use MongoDB before submission)

* POST /api/auth/login — authenticates and returns a JWT

* At least one protected route that requires a valid JWT to access

* JWT middleware validates the token on every protected request and used by controllers

server.js = what -> 
app.js = how (orchestrates our routes) -> 
routes -> 
middleware = (is it valid) -> 
controllers (logic) -> 
data -> 
response 

Separation of concerns:

- Controllers/authController
-middleware/validateAuth
-utils/generateToken
-routes/authRoutes

 and security decisions (hashing, JWT flow, validation, HTTPS — why it was used specifically in
